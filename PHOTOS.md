# Adding photos

Photos live in Cloudinary. The site reads `photos-data.json` (the list of photos) and
`photo-captions.json` (captions), both generated by `scripts/update.js` and kept fresh by
the **Sync Photos** GitHub Action (`.github/workflows/sync-photos.yml`).

## From the phone (Pixel)

1. In Google Photos (or Files), tap **Share → Post photo**.
2. Type a caption, or leave it blank.
3. Done. The photo uploads to Cloudinary, the shortcut pokes the Sync Photos action, and
   the site updates in a minute or two.

The upload preset shrinks each photo to at most 2560px and re-encodes it, which also
**strips location data** before it is stored.

## Captions

- Typed on the phone → saved on the photo in Cloudinary → copied into
  `photo-captions.json` on the next sync, if that photo's slot is still empty.
- Or edit `photo-captions.json` directly. A caption written there always wins, and syncs
  never overwrite or delete one.
- Avoid `|` and `=` in phone captions (Cloudinary uses them as separators), or escape them
  as `\|` and `\=`.

## From the computer

```bash
npm run update:photos
```

Needs the Cloudinary keys in `.env` (with `CLOUDINARY_FOLDER=` left empty, since the photos
sit at the root of the account).

## One-time setup

### 1. Cloudinary upload preset

Cloudinary console → **Settings → Upload → Upload presets → Add upload preset**:

| Setting | Value |
| --- | --- |
| Name | something unguessable, e.g. `site-` + a random string |
| Signing mode | **Unsigned** |
| Use filename / Unique filename | on / on |
| Tags | `phone-upload` |
| Incoming transformation | `c_limit,w_2560,h_2560/q_auto:good` |

Treat the preset name like a password: anyone who has it can upload to the account, and
those uploads would show up on the site. Keep it only in the phone shortcut, never in this
repo. If it leaks, delete the preset and make a new one.

### 2. GitHub

- **Actions secrets** (repo → Settings → Secrets and variables → Actions):
  `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
- **A token for the phone**: github.com → Settings → Developer settings → Fine-grained
  tokens → Generate. Repository access: *only* `arkanemystic.github.io`. Permissions:
  **Actions: Read and write** (nothing else). This token can only start workflows; it can't
  touch code.

### 3. HTTP Shortcuts (Play Store, free)

**Shortcut A: "Refresh site"**

- Method `POST`, URL
  `https://api.github.com/repos/arkanemystic/arkanemystic.github.io/actions/workflows/sync-photos.yml/dispatches`
- Headers: `Accept: application/vnd.github+json`, `Authorization: Bearer <phone token>`
- Body: custom text, type `application/json`: `{"ref":"main"}`
- A `204` response means it worked.

**Shortcut B: "Post photo"**

- Create a variable `caption`: type *Text Input*, prompt "Caption (optional)".
- Method `POST`, URL `https://api.cloudinary.com/v1_1/dqpl3a9gb/image/upload`
- Request body: *Form data (multipart)* with three parameters:
  - `file`: type **File**, set to use the file shared into the shortcut
  - `upload_preset`: `<your preset name>`
  - `context`: `caption={caption}` (insert the variable)
- Trigger & Execution settings: allow the shortcut to **receive shared files**, so it shows
  up in Android's share sheet.
- Scripting → *Run on success*: add the **Trigger Shortcut** action pointing at
  "Refresh site", plus a toast like "Posted, site updates in ~2 min".

Test it once with a throwaway photo, then check the **Actions** tab on GitHub: a *Sync
Photos* run should appear, and the photo shows up on `/photos` once Pages redeploys.

## If something goes wrong

- **Photo uploaded but not on the site:** open the Actions tab and look at the latest *Sync
  Photos* run. The 6-hourly schedule retries on its own too.
- **Sync run fails:** usually a Cloudinary secret is missing or wrong. The script stops
  without touching the photo list; it never saves an empty one.
- **Remove a photo:** delete it in Cloudinary, then run *Sync Photos* manually (Actions tab
  → Sync Photos → Run workflow) or wait for the schedule.
